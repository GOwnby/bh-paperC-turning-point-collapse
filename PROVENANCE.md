# Provenance of this repository (Paper C and its supplementary technical report)

Plain statement of how this repository relates to the author's original files. Written from an audit that compared this repository with the original archive
(file tree, `diff` and checksums) and re-ran original scripts. Evidence files of that audit are in `provenance_evidence/` (outputs of the ORIGINAL scripts).

## 0 Baselines used in this file

Three states are compared: (1) the author's tree `old_archive/1_sources/sources/<paper>`; (2) the first Zenodo release (the initial git commit of this repository); (3) the current repository. On 2026-10-21 (1) and (2) were compared byte for byte: they are identical except for the repository metadata (`.gitignore`, `.zenodo.json`, `CITATION.cff`), the compiled PDF and a copy of the technical report (`technical_report_phase2/`). The rest of the old archive (`old_archive/2_docs_and_archive_1/archive/`: earlier manuscript versions, session logs, audit directories) was searched for code and data behind this paper's results; files found there that are not in the Zenodo release are listed below where they matter. The audit scripts and logs of the earlier sessions that were not in the Zenodo release (`archive_paperC_combined/audit*`) are shipped unchanged in `code/audit_original/` (see its README). Wherever this file says "original" or "v1.0.1" it means (1) = (2).

## 1. Lineage

- The original files are the author's archive, identical in content to Zenodo version 1.0.1 (`paperC_turning_point_collapse/` and `technical_report_phase2/`). This repository is a
  reorganization of them: new top-level layout, `README.md` files, `verify.py` / `verify.sh` / `verification/`, regenerated logs, and a few edited or added scripts.
- The audit (October 2026, an automated review by Claude Code at the author's request) classified every differing file as **a** (cosmetic: paths, comments, timing, additive output),
  **b** (bug fix) or **c** (functional change that can alter output) and proved b and c by running the original and the changed file.
- **Since v1.0.1 the repository also contains new work that is not in the Zenodo archive:** `technical_report_phase2/ancillary/lagrangian_L/` and its checks (section 7); generated by an AI assistant, independent of the lost original driver.
- Policy applied: original results and scripts are not silently replaced. Where a file differs from the original, this file says so and gives the run that justifies it. Where
  the original is the correct object it has been restored (`code/fold_dyn2.py`, `code/fold_dyn2.json`, `euler_module_seeded.py`).
- `main.tex` of this repository differs from the original manuscript (references, wording, a regenerated turning-point table, softened claims); the word-level differences were
  reviewed. Every number changed relative to the original manuscript is listed in section 4.

## 4. Results that changed relative to the original

- **Turning-point table (Sec. 3.7).** The original manuscript quoted rho at the mass peak 2.31052 / 2.34614 / 2.38553 / 2.40183 / 2.93210 (x1e13 kg/m^3) and differences 0.010 / 0.009 / 0.008 / 0.007 / (0.007) %.
  They came from `survey4.json`, where the peak is located with a maximizer tolerance `xatol = 1e-4` in log10 rho. `turning_point_table.py` uses 1e-8 and gives 2.31060 / 2.34621 / 2.38557 / 2.40187 / 2.93211 and
  0.0061 / 0.0061 / 0.0062 / 0.0061 / 0.0065 %. The peak is a maximum, so a coarse tolerance can move it by up to about 1e-4 relative (here 3e-5). The paper now quotes the 1e-8 values. The abstract, Sec. 3.7 and the conclusions
  now say "within 0.007 %" (the largest entry; "0.01 %" was the old value, "0.006 %" would be false for iron). `survey4.json` still holds the 1e-4 peak position.
- **Fold passage (Sec. 5.6).** `fold_dyn2.json`: the 14 rows of `out` (Table 3) are identical in the original and in the regenerated file (bit for bit). Only the `PI` field differed: a modified `fold_dyn2.py` replaced the
  early pole estimator (initial slope with the wrong sign: values 3.32, 3.35, 3.47, 3.46 for start points -20 ... -60; 3.3157, 3.3454, 3.4659, 3.4534 in the shipped json, written by a slightly earlier version of the block)
  by the estimator of `pi_tritronquee.py` (3.41167). Restoring the original keeps the evidence for the manuscript's statement that an earlier estimator scattered between 3.3 and 3.5. The original manuscript said the
  earlier estimator "gave 3.4101"; no file in the archive produces that number. The paper's s_* = 3.41167 comes from `pi_tritronquee.py` (run on the original code: 3.4116718).
- **Other numbers of the manuscript changed from the original** (all backed by `verify.py` checks and logs): critical mass attribution (1.4176 is quoted by Mathew and Nandy, whose own value is 1.4166), 1.4252 -> 1.4254,
  grid dependence +0.022 / +0.0018 / +0.0008 -> +0.021 / +0.0012 / +0.0001, sigma^2 of the first implementation -41.05 -> -41.09, the plunge independence "nine significant figures" -> "six" for delta_0 = 1e-3 ... 1e-12 (measured spread 1.5e-7),
  several Table 6 digits (0.177 -> 0.175, 0.0531 -> 0.0532, 364 -> 365 s), Hamiltonian-constraint values, the sentence on the first implementation (zero at 1.86e13).
- **Technical report, Sec. 4 and Sec. 2 (Lagrangian).** Replaced by the re-do of section 7: crossing times 14.2 / 9.1 and "35 % sooner" are no longer results; Sec. 2's "R'/X independent of tau" and the factor a^2 are corrected; the first loss of ordering is at t = 59 / 66 L/c in the outermost zones (ratio 1.12, not 0.64) and the neutronized core runs away only with viscosity. The report's stable control (rho_c = 1e11 kg/m^3, linear +4.65 s^-2 and Eulerian scan) is a star cut at 3000 km (`build_star(rho_c, rmax=3e6)`); +1.756 s^-2 for the complete star.
- **Technical report, Sec. 7.2.** The original `euler_module_seeded.py` has no stop test; after the central density runs away the density floor keeps rho > 0 and the run goes on with dt -> 0 until the wall-clock budget (log: v_c = -1.9e43 m/s).
  The quoted t = 0.618 s for N = 1600 is the time at which that state was reached. The guarded module stops there (max|v| > 1e12 m/s) with identical results before the stop; the central density has risen by a factor 4e6 (not "six orders" exactly).
  The "2.45x at t = 0.545 s" of Sec. 7.4 is not a logged value; the bracketing samples are quoted.

## 6. Known limits

- **Not rerun here:** `verify.sh --full` jobs (`lagrangian_L/run_all.sh` 13 min, composition survey 16 min, `turning_point_table.py` 10-25 min, Lagrangian N >= 400, `figs.py`, `study2.py` 45 min for N = 6400, `control_test.py` N = 3200, ...). Their shipped logs were compared with the manuscript only.
  `--checks-only` re-reads shipped logs and is circular by construction.
- **Sympy-based logs** (`code/symbolic/`, `analytic_check*`, `verify_pure_mode`, `verify_exact_poisson`) could not be rerun in the audit environment (no sympy); statements marked "verified symbolically" rest on those logs.
- **Technical report, the Lagrangian shell-crossing runs of the first version (crossing times 14.2 / 9.1) are not reproducible**: the original driver, `evolve_neu.py` and `collapse_neu.py` were not retained, and no converged calculation reproduces them (section 7).
  The symbolic computations of Sec. 2 of the report (divergence of T, Einstein tensor with a = 1) have no retained script; the Misner-Sharp identities are re-verified for a general lapse by `lagrangian_L/src/verify_ms_equations.py`.
- **Eulerian scripts depend on a wall-clock budget** by default (85-260 s); the N = 1600 row of the convergence table needs far more on a slow machine (`WALL_BUDGET`). `euler_convergence.py` and `study1.py`
  give 1.0807 and 1.0794 for N = 1600 (the table quotes 1.079). The N = 400 mass ratio is not printed by any shipped log; an audit run of `euler_module.py` gives 0.999991 (not six digits; `provenance_evidence/euler_module_N400.out`).
- **`survey4.json`** locates the mass peak with `xatol = 1e-4` (see section 4); the survey table of the paper is insensitive to it, the turning-point table is not and uses `turning_point_table.py`.
- **`fold_dyn2.json` `PI` field** is the superseded estimator (see `code/README.md`); it is used only as evidence.
- **Loose tolerances in `verify.py`** (relative > 1 %): quantities quoted with one digit (e.g. `EOS-Pc2`, `EOS-epsrho`, `PEK-zero`, `HOM-equip`, `TP-grid48000`), two-digit table entries (`FT-*-dM`, 4 %), and "about" statements
  (`FT-Mdot-pow` 6.35 vs 6, `SV-iii-a`). Each carries its reason in `verification/expected.json`. The tolerances of `TP-abstract` and `FS-plunge-indep` were tightened/corrected in this change.
- Figures 5, rayleigh-ritz convergence and fold passage: original generators; Figures 1, 8, Friedman: re-creations (section 3).

## 7. `technical_report_phase2/ancillary/lagrangian_L` (new work after v1.0.1)

- **What, by whom.** A staggered conservative Misner-Sharp scheme with tests, logs and tables that re-does Sec. 4 of the report (Lagrangian evolution, shell crossing). Written and run by an AI assistant (Claude) in the session that also rewrote Sec. 4, the two corrections to Sec. 2, the abstract and the Established / Not established paragraphs. **Independent of the lost original driver** and of the author's Lagrangian code; it uses the author's code only through the 11 byte-identical copies in `ref/` (EOS, neutronization, profiles, Galerkin solver, `stable_crosscheck.py`, `apply_to_real_star.py`, and the first-version `evolve2.py`, `collapse2.py`, `lagrangian_envelope.py` for the replica; check `LG-ref-sums`).
- **What it replaces.** Sec. 4 of the first version (14.2 / 9.1 light-crossing times, "35 % sooner", the spline re-creation as a stand-in for the lost driver) and two statements of Sec. 2. The author-written 14.2 and 9.1 are **not reproduced** by any converged calculation (first loss of ordering at about 59 and 66 L/c, ratio 1.12) and their origin is unknown (the exact replica of the re-creation gives 14.783 / 2.188, not 14.2 / 9.1).
- **Checks.** 278 quick checks `LG-*` compare every number of Sec. 4 (text and tables), of the abstract and of the Established / Not established paragraphs with the shipped logs, `results/*.json` and `RESULTS.md` (half a unit of the last digit unless stated), plus the 23 PASS lines, the 17 exit codes, and the `ref/` checksums (also against this repository's scripts). They are circular with respect to the shipped files, not with respect to the manuscript. Checks tagged `[after edit R2-n]` quote the report as changed by `tr_main_tex_edits_round2.json`: quoted values that disagreed with the shipped results (pure vs neutronised radius deviations 2.2e-4 / 2.1e-4, neutronised drift 1.0e-2 / 1.1e-2, 122 / 122-123 %, observed order of rho_c 1.6 and not 2.0-2.2, mass radii 1e-5 / 2e-5, fixed-step core zones, truncated control).
- **Not in any shipped log** (derivation or hand estimate): delta(Gamma^2) ~ 1e-4 ... 1e-3 during the runs and "removes the support of the outer 3-4 nodes" (`derivations.md`; the log lists 4 nodes). Produced for this change by `lagrangian_L_extra_checks.py`: first-step kick 0.561-0.566 g dt for N = 100 ... 1600; 1 - a at the centre 0.348 % (pure), 0.311 % (neutronized); zones of the fixed-step core crossing.
- **Limits.** (i) The independent GR Sturm-Liouville solver (`linear_gr.py`) and the scheme (`lag.py`) were written by the same author (the assistant): their agreement (2e-5 ... 3.4e-5) excludes errors of discretisation and of the linearisation, not a common misreading of the equations. The equations are checked by exact 2-jet differentiation of the Einstein tensor (identities I1-I6; I5 = lapse equation a'/a = -p'/(e+p), I6 = energy equation; negative controls) and, for p = 0, against the exact Oppenheimer-Snyder / Lemaitre-Tolman-Bondi cycloids (`test_i_dust.py`, observed order 2.00). The pressure terms have no exact nonlinear comparison solution; they rest on the static, linear-mode, convergence and conservation tests. (ii) t is the proper time of the outermost shell (a = 1 at the surface), in units L/c of the report's Newtonian radius; the time at infinity is longer by 1/sqrt(1 - 2M/R) = 1.0013 (pure), 1.0011 (neutronized). (iii) The edge crossing time does not converge with N (58.97-59.55 and 66.14-66.93): "59.3 +- 0.3", "66.5 +- 0.4" are ranges, not errors. (iv) Spherical, barotropic, EOS tables end at 1e16 kg/m^3; nothing is claimed past 300x. (v) `run_all.sh` takes 20 min (1177 s); it was run twice from scratch on the final scripts (round 3) and the two runs agree in every number, only the 63 wall-clock timing fields differ; the shipped logs are the second run. (vi) `test_d_edge.py` runs N = 400 only; "every N" for the first-step kick rests on `lagrangian_L_extra_checks.py`.
- **Round 3 (this revision).** Auditor flags on the Lagrangian result answered: (a) the size of the variation of Gamma^2 is now measured (`test_j_gamma_size.py`: max |dGamma^2| = 2.7e-4 pure, 2.5e-4 neutronised, about 6 % of the largest 2m/R) instead of estimated; (b) the 3-/4-node statement is in `logs/repro_spline.log`; (c) lapse and energy equations are machine-verified (I5, I6 in `verify_ms_equations.py`); (d) **a defect of my own scheme was found and fixed**: the coupling rho_N - m - Gamma was iterated 3 times, which reduced the order to about 1.1 for strong-field dust, and it is now iterated to 1e-13 (`gtol`, `n_iter_max = 200`; weak-field results change by <= 1e-10 and all verdicts are unchanged: converged inviscid first R' <= 0 at about 59 (pure) and 66 (neutronised) L/c; with viscosity the neutronised core collapses, the pure star peaks at 5.44x); (e) independent validation by the exact dust cycloids (`test_i_dust.py`: relative error in R(t) 1.8e-7 / 1.4e-7 at N = 400, order 2.00); (f) a second full run of `run_all.sh` reproduces the first in every number (only timings differ). `verify.py --checks-only`: **886 of 886 checks PASS** (608 + 278 `LG-*`). The 872/264 figures above refer to round 2. `code/audit_original/` holds the auditor's round-1/2 scripts from the old archive (`archive_paperC_combined/audit`, `audit2`), unmodified.
