# Delayed Collapse of a Degenerate Core at Its Maximum Mass: General-Relativistic Instability and the Fold-Passage Law

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.23455581.svg)](https://doi.org/10.5281/zenodo.23455581)

**Author:** Gracen Ownby. **Archive:** <https://doi.org/10.5281/zenodo.23455581>. **Licence:** code MIT, text and data CC-BY-4.0 (see `LICENSE.md`).

Paper C of a seven-paper series (A to G) on Hayward-type regular black holes. This repository contains the LaTeX source, the compiled PDF, the figures, and every
script, log and data file that produces a number, table or figure of the paper.

## Verify

```
pip install -r requirements.txt
bash verify.sh --quick    # 22 min CPU (measured; on two free cores the wall time is estimated at 11-12 min): re-runs every cheap generator and re-derives all 886 quoted numbers, tables and figure statements (long jobs: from their shipped data)
bash verify.sh --full     # additionally re-runs the long jobs (a further 162 min CPU, of which 25 for the Lagrangian re-do of the technical report; measured; estimated 1.5 h wall with `--jobs 4` on four free cores)
```

Output: `verification/REPORT.md` (PASS/FAIL table with the paper location, quoted value, tolerance and reason, computed value, environment, run time per step), `verification/logs/<script>.log`, `expected.json`, `results.json`; exit status non-zero on a failure; last line `RESULT <repo>: PASSED n/n checks (quick)`. Steps whose module (`scipy`, `sympy`, ...) is missing print SKIPPED and their checks use the logs shipped in `verification/logs`. Options: `--only a,b`, `--jobs N`, `--checks-only`, `--list`.

## Abstract

For the idealized cold electron gas (Chandrasekhar equation of state) the paper locates the maximum mass with the TOV equation (1.4166 solar masses), implements
Chandrasekhar's general-relativistic radial pulsation equation and tightens its fundamental eigenvalue by Rayleigh-Ritz to sigma^2 = -28.55 s^-2 (e-folding time
0.187 s), and passes the exact turning-point test (the eigenvalue vanishes where the mass peaks) to within 0.007% for five equations of state; a first implementation failed
this test, which exposed two errors that are corrected and documented. The nonlinear outcome (collapse for compressive perturbations) is taken from the numerical-relativity
literature. A calibrated one-degree-of-freedom nonlinear model is compared with an independent spherical general-relativistic Lagrangian evolution (time to half the
initial radius to 0.4%, plunge to 1-3%), and a star that reaches the maximum by slow accretion is treated as a ramped saddle-node bifurcation described by the first
Painleve equation, giving a collapse delay t = 3.41 (4a/(kappa^2 Mdot))^(1/5) in terms of two exact-GR fold coefficients. The matter is an idealized gas that neither
neutronizes nor bounces; the companion Paper D replaces it by a dense-matter equation of state.

## Build the PDF

From the repository root, with a standard TeX Live installation (pdflatex, bibtex, natbib, hyperref):

```
pdflatex main
bibtex main
pdflatex main
pdflatex main
```

This produces `main.pdf` (31 pages) with no undefined references or citations. (An equation sits at a page break, so the third pass may print the harmless message "Label(s) may have changed"; one more `pdflatex main` removes it and does not change the text.) The shipped PDF is the result of four `pdflatex` runs. The technical report is built the same way inside `technical_report_phase2/`.

## Reproduce the numbers and figures

Requirements: Python 3 with NumPy >= 2.0, SciPy, Matplotlib and (for the symbolic checks) sympy and mpmath (tested versions in `requirements.txt`): `pip install -r requirements.txt`.
No external data and no network access are needed: the equation of state is analytic and all constants are defined in `code/background.py`.
**All commands are run from the `code/` directory** (`cd code`); scripts use paths relative to their own location and write the figures to the repository root.
The commands below redirect the screen output to the logs that are shipped in `code/` (so the shipped logs are exactly what these commands print).
CPU times (user + system, one core) were measured by `verify.py` on a shared Linux machine with two cores while other jobs were running; wall-clock times are in `verification/REPORT.md`. Most scripts take seconds to a few minutes.

Platform notes: developed and tested on Linux. On Windows use WSL, or adapt the shell redirections (`> file.log`) to your shell.

### Supplementary technical report (`technical_report_phase2/ancillary/`)

`verify.sh` also runs the scripts of the technical report whose numbers are quoted in this archive (equation of state, Chandrasekhar mass, neutronized EOS, the Galerkin eigenvalue
of the marginal star -18.68, the cross-checks -16.65 and +4.65 s^-2 (the latter for a star cut at R = 3000 km; +1.756 s^-2 for the complete star), the Eulerian convergence table, the control run, the seeded evolutions); each writes `<script>.log` next to the script
(run from inside its directory, `PYTHONPATH=..` for the subdirectories). The Eulerian scripts stop after a wall-clock budget (85-260 s) by default, which under a loaded machine cuts the runs short;
`verify.sh --full` sets `WALL_BUDGET=100000` so that they reach their final time. The seeded runs of Sec. 7 of the report use `euler_module_seeded_guarded.py` (the archive's `euler_module_seeded.py`, unchanged, plus a stop at |v| > 1e12 m/s) in `verify.sh`, so that the end of a run does not depend on the speed of the machine; `check_guard_equivalence.py` shows that the two modules give identical states up to the stop; the logs of the original module are `run_seeded2.log`, `run_seeded_strong.log`, those of the guarded one `*_guarded.log`. See `PROVENANCE.md`. Not reproducible: the Lagrangian shell-crossing runs of the first version of the report (crossing times 14.2 and 9.1; the driver and `evolve_neu.py`, `collapse_neu.py` were not retained). They are replaced by the convergence-verified re-do in `lagrangian_L/` (next paragraph); `lagrangian_envelope.py`, `evolve2.py` and `collapse2.py` belong to the first version, and `lagrangian_envelope.py` is shown in Sec. 4 of the report to give a discretisation artefact.

### Convergence-verified Lagrangian re-do (`technical_report_phase2/ancillary/lagrangian_L/`, Sec. 4 of the report)

New work added after version 1.0.1 (not in the Zenodo archive; `PROVENANCE.md`, section 7). `lagrangian_L/` holds a staggered conservative Misner-Sharp scheme (`src/`), the tests (a)-(h) of Sec. 4, their logs (`logs/`) and results (`results/*.json`, `results/RESULTS.md`), `derivations.md`, and byte-identical copies of the report's routines (`ref/`, checksums in `logs/ref_checksums.log`); its own `README.md` gives the layout and the findings.
`bash run_all.sh` (inside that directory; numpy and scipy only) regenerates everything in about 20 minutes on two cores (1177 s wall; `logs/wall_time.log`). `verify.sh --quick` does **not** run it: it compares every number of Sec. 4, of the abstract and of the Established / Not established paragraphs of the report with the shipped logs and results (checks `LG-*`, 278 of them), re-reads the PASS/FAIL lines of the logs and the `ref/` checksums, and runs `lagrangian_L_extra_checks.py` (45 s: first-step kick for N = 100 ... 1600, central lapse offset, zones of the fixed-step core crossing). `verify.sh --full` also runs `run_all.sh` in a copy (`verification/work/lagrangian_L`; the shipped files stay as shipped) and evaluates the same checks on the regenerated files (`LG-regen-*`).

The scripts that are not listed above (`background.py`, `metric.py`, `lag_gr.py`, `homologous_calibrated.py`, `twomode.py`, `survey.py`, `fold_inhom.py` as a module, ...) are libraries
used by the scripts above. `fold_inhom.py`, `fold_dyn.py`, `homologous_calibrated.py`, `lag_gr.py`, `metric.py`, `tov_solve.py`, `background.py` and `fold_step1.json`
are also the hand-off code used by the companion Paper D; `python3 -c "import fold_inhom; fold_inhom.handoff"` run in `code/` must succeed.

Known limitations of the archive: the Lagrangian shell-crossing runs of the first version of the supplementary technical report (crossing times 14.2 and 9.1 light-crossing times) cannot be rerun, because the driver and the two neutronized-EOS scripts (`evolve_neu.py`, `collapse_neu.py`) were not retained, and no converged calculation reproduces them. `technical_report_phase2/ancillary/lagrangian_envelope.py` (first-version re-creation: t = 14.78 for the pure EOS, innermost shell; t = 2.19 for the neutronized EOS, outermost shell) is shown in Sec. 4 of the report to be a discretisation artefact, and `evolve2.py` has two errors (a^2 instead of a; R'/X frozen). The re-do in `lagrangian_L/` replaces them: first loss of ordering at t = 59 (pure) and 66 (neutronized) light-crossing times in the outermost zones, ratio 1.12 and not 0.64; its limits are listed in `PROVENANCE.md`, section 7. The report's stable control (rho_c = 1e11 kg/m^3; linear analysis and Eulerian resolution scan) is a star cut at R = 3000 km.
Only the Newtonian Galerkin solver of the report is used by this paper (Fig. 1, Section 3.1-3.2).
